### 一、使用方式

浏览器打开即用，免注册；手机与电脑同链接，微信内置浏览器会被拦截，需用系统浏览器。

**入口 1 · 事实核查（一句话）**
粘贴一句待核实的说法 → 点「开始核查」→ 系统自动拆子主张 → 用元宝搜索做三轮真实检索（广泛取证 → 交叉验证找反方 → 溯源一手材料，最多 9 次）→ 给出「真 / 假 / 误导 / 说不准 / 没查到」五档结论，每条关键依据都附**可点开的原始来源**；点「查看取证过程与判决依据」可看到三轮分别查了什么词、命中哪些页面。

**入口 2 · 文案体检（整段文案）**
把要发的文案整段丢进来 → 点「生成体检结果」→ 拆句后分两路：违禁词句按《广告法》明文判定、0 次检索秒出；其余句子里的事实宣称取前 8 句逐句检索 → 输出等级（A/B/C/D）、分数与逐句给出修改建议（哪句要改、改成什么、依据哪条）。

**入口 3 · 截图也能查**
上传海报或截图 → 本地 OCR 认字后自动回填输入框→ 再走上面任一入口。

**查完之后**：结果页最下面点「可转发卡片」或「导出报告」，可以保存为图片或核查报告，可打印成 PDF（示例 /r/0160），转发给合伙人或老板确认。

### 二、亮点

**三句话说清它值钱在哪。**

**① 卡在「发布之前」——罚款是可以预防的，不是只能事后道歉**
- **痛点**：违法广告单案罚款 40.98 万元（市场监管总局通报，见附 A 提问 3）。这笔钱只有在文案发出去**之前**才拦得住。
- **做法**：整段文案、海报截图直接丢进来 → 数十秒出等级（A/B/C/D）+ 分数 + **逐句改法**（哪句要改、改成什么、依据哪条）；结果可「导出报告」打印成 PDF，在签字发出前让合伙人和老板过一遍。
- **实测**：一张 597 字双栏服务海报 → 本地 OCR 全文识别 → 8 秒出 **B·84 分**与逐句改法。
- **场景创新**：GitHub 上三个最接近的开源项目都是"内容已经流出后再核查"，本作品面向**还没发出去的那一段文案**——这是场景上的差别，不是功能上的。

> **小结**：技术上是一条"**句子级路由 + 本地离线 OCR + 逐句改写建议**"的流水线——解决的是"等被罚了才知道那是虚假宣传"的滞后。对标的最佳实践回答"这条内容真不真"；我们在这个答案上往前多走一步：**给等级、给分数、给改法、给可打印的结论**，让老板在签字之前就能改。同样的核查能力，交付的是可执行的动作，而不是一句判语。
>
> **比最佳实践多走一步**：它们止于 verdict（判语），我们止于 **rewrite（改法）**——用户真正要问的从来不是"这句话真不真"，而是"这句我能不能发、发了会不会罚款"。

**② 结论由规则下、每条点得开原文——不把真假押在模型"看起来很确定"上**
- **做法**：模型只做两件小事——拆子主张、给单条证据打立场标签；真假由规则按权威层级算出，并且永远保留第五种答案「没查到可靠来源」。
- **收益**：结论可复现、可被第三方复核——同输入同输出，6 例离线回归每次改代码都跑。也因为这套裁决链，它敢把**拒答率 16.9%** 当指标亮出来，而不是藏起来。
- **实测**：线上 71 次查证 / 381 次真实检索 / 1,270 条来源，全部可在 `/stats` 与「查证墙」逐条对账。
- **留余数的诚意**：真/假最高只到 90（62 + 8 × 独立权威条数），单条权威不下结论（只给「说不准」）。曾经把"美国下一届总统是谁"判成「真 · 83」——错得很有信心，我们把这次事故连同原因写进 `policy.py` 注释当护栏。

> **小结**：技术上把大模型**从"裁判"降级成"标注员"**——它只做两件能被规则校验的小事（拆子主张、给单条证据打立场标签），判决交给几十条确定性规则按权威层级与证据一致性算出，任何一步改动都会被 6 例回归抓住。对标的最佳实践是提示词/评分细则驱动的模型（Claude Code 技能、LangGraph 链路），换模型或换版本就可能漂移；我们这里是代码：**同一个说法今天查和明年查，结果一样**。
>
> **比最佳实践多走一步**：它们的置信度来自模型自评，我们的来自一条手也算得出的公式——`min(90, 62 + 8 × 独立权威条数)`。**第六档「不在受理范围」也是多出来的**：碰个人私事与时政，一次检索都不发生，而不是"礼貌地答非所问"。

**③ 中文广告场景的双路判定（创新点）：违禁词走法条秒出，事实宣称走检索附来源**
- **做法**：同一段文案里两条路分工——《广告法》明文类表述**0 次检索**直接给"依据哪条、改成什么"；需要外部举证的事实宣称才做真实检索。反向也讲克制：一句话传言只判真假，**不按《广告法》查违禁词**（传言没有广告主和商品，广告法不适用）。
- **收益**：既秒出，又说得出道理——词库型工具只会把词标红，说不出"错在哪、该怎么改"；同时正常文案不误杀：能自证的（开了几年、人均多少）只提示留存材料。
- **实测**：「全网最低价 / 国家级 / 立竿见影」→ 3 处高危全部给出依据与改法，**检索次数 0**（「国家级」直接引《广告法》第九条）。
- **中文本地化**：设问式标题、否定式表述、繁体字、辟谣稿——这四类会把开源工具的立场判断直接带反，本作品用规则闸门兜住；另有企业信用专项口径（只认政府司法公示）与 misleading「误导」独立档。

> **小结**：技术上是一条"**先路由、再决定要不要检索**"的双引擎——《广告法》明文类命中结构化法条库（每条自带"依据 + 改法"字段，0 次检索），其余才进真实检索。对标项目对每条主张都搜一遍（bullshit-detector 的示例报告自己写着：**60 条主张逐条搜了 44 条**），成本随字数线性增长；我们把不需要外部举证的句子挡在检索之外，把预算留给真正要核的句子。**更准，也更快**：一张 597 字双栏海报，8 秒出等级、分数与逐句改法（记录 0179）。
>
> **比最佳实践多走一步**：它们只决定"要不要检索"，我们多一层"这句要不要外部举证"——能自证的只提示留存材料，需要外部举证的才发起检索。这一层决定了噪音与账单的上限。

**这三点不是自说自话。** 开发中逐条对照了 GitHub 上三个最接近的开源项目——**bullshit-detector**（<https://github.com/SerhiiKorniienko/bullshit-detector>，2026-10-23 查询时 158★，逐主张核查 agent，README 原话："没有来源就不给结论，哪怕模型很确定"）、**ClaimeAI**（106★，LangGraph 拆解主张）、**FIRE**（MBZUAI 实验室，27★，迭代检索查证框架）。**对照结论：它们的最佳实践，本作品一条不落。**

|---|---|---|

| 主动搜「反驳角度」，不重复搜同类 | 第二轮专门攻矛盾（refute 检索） | 结果卡「查看取证过程与判决依据」→ 看三轮查询词 |

**两处刻意没照抄（取舍就写在代码注释里）：**
- **FIRE 的"动态停止"省检索成本**：本作品曾经实现过提前收手，因为有争议的说法会漏掉交叉验证与溯源而**主动删掉**——宁可多花三次检索，不在证据链上偷工。
- **bullshit-detector 的转载合并照做了，中文场景下另补三道**：媒体转述降级（「报道某研究说」≠ 支持）、同站矛盾清零、同站去重——中文门户的转载密度远高于英文。

### 三、实现思路

**技术栈**：Flask 单端口 + SQLite，无外部 CDN，断网不白屏；OCR 走本地 RapidOCR，不传图、不耗额度；检索走元宝搜索（腾讯云 wsa-standard）。

**主链三段式：检索 → 证据分级 → 判决。**

- **检索**：按子主张生成查询词，三轮递进，每轮换角度（先广后深再溯源），单句最多 9 次。宁可"没查到"，也不拿营销号凑数。
- **证据分级**：每条证据标站点、日期、立场（支持/反驳/中立）、权威度；一条证据要过 13 项筛查（立场标注、否定式守卫、因果降级、转述降级、同站矛盾清零、同站去重、转载合并、疑问句降级、辟谣标记、主体校验，再加企业信用、主体冲突、主题相符）才允许进入判定。
- **判决**：规则按权威层级与证据一致性算出结论与置信度，**模型不直接给真假**。真/假档最高只到 90，且要由多条独立权威堆叠（62 + 8 × 条数，封顶 90）；说不准 20–60；没查到 0–10。判定链可复现、可解释、可被人工复核。
- **体检评分**：100 − 高危×18 − 中危×8 − 判「假/误导」句×10；判假句占已核查一半以上直接封 D 且分数压到 54 以下，否则 A/B 降到 C。长文设 55 秒时间预算，超时句标「待核查」而不是硬给结论。
- **为什么这么设计**：把"会不会说错"这件事，从模型的概率里拿出来，交给可核对的规则与来源。代价是慢一点、有时会拒答；收益是**说出的每句话都能点开原文对账**。

**已知边界（我们明确不做什么，写在这里而不是藏在试用条款里）：**

1. **不受理两类问题**：个人私事（信用、品行、隐私、家庭）与时政，入口直接拒答，**一次检索都不发生**。词表故意不含「政策」「政府」这类通词——「某市取消限行政策」属于可核实的公共事务，不能误杀；问企业也不拦。
2. **不替代专业意见**：结论页固定挂免责声明（原文：*本结果基于权威、可公开核验来源的核查与风险提示，不构成法律意见。*）
3. **不判推理是否成立**，也不验个人/企业资质的真假——只提示"补证书/补证明"，不替机构背书。
4. **检索本身有不确定性**：来源自己错了我们会跟着错，所以每张卡都标查询时间与检索次数，请把链接点开复核；高权威站点反爬时宁可"没查到"，也不拿营销号凑数。
5. **有容量上限**：体检输入 1,000 字以内、单句核查 200 字以内；体检只深查前 8 句，55 秒到点即停，没查的句子标「待核查」。
6. **会降级但会写明**：无密钥或接口异常时自动切到演示数据、页面标注，绝不白屏；线上 `/stats` 的 71/381/1,270 全部是真实环境下的计数。
7. **不做持续盯梢**：那是运营能力，做不好反而给出过期提醒——主动交代取舍，而不是硬凑功能。
