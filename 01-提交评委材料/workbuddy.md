## 1. 一句话说清这个作品

丢给它一句话或一段要发布的文案，它去网上查三轮，带着**可点开的原始来源**回来；证据不够就明说"没查到"，涉及个人私事与时政直接拒答。

核心判断：**AI 最容易被骂的不是不会，是"说错说得太自信"**。所以产品的第一性目标是"宁可说不知道，也不编"，而不是"什么都能答"。

## 2. 开发过程（按对话顺序，含真实返工）

### 2.1 立项与骨架（10-22）

| 步骤 | 做了什么 | 关键决策 |
|---|---|---|
| 1 | 确认赛道：侦探「查得到，信得过」，只报一条赛道、单人参赛 | 不重复提交，避免被判违规 |
| 2 | 定架构：**检索 → 证据分级 → 判决** 三段式，LLM 只做两件小事（拆子主张、打立场标签），结论由 `judge.py` 规则算出 | 拒绝"套壳聊天机器人"路线：模型不参与下结论，才能同输入同输出 |
| 3 | 定五档结论：真 / 假 / 误导 / 说不准 / 没查到 | 多出「误导」档，用于张冠李戴类说法 |
| 4 | 定检索预算：核查 3 轮 / 最多 9 次；体检每句 1 轮 / 最多 3 次（8 句合计 24 次） | 轮=回合，次=接口调用；一轮内多条并发 |
| 5 | 搭 Flask 单端口 + SQLite，写完 `detective/` 12 个模块 | 无外部 CDN，断网可降级演示 |

### 2.2 判定链踩过的坑（10-22 — 10-23）

每一条都是**先出错误结论、再定位、再补规则**，不是设计出来的：

| 事故 | 现象 | 修法 |
|---|---|---|
| 否定句读反 | 模型把《澳专家：喝咖啡不會增加患癌風險》标成**支持**，整条判真 | 否定式守卫：出现"不会增加/不致癌/没有证据表明"只能算反驳，繁体一并折叠 |
| 设问标题 | 《隔夜菜真的会致癌吗?》被判成支持 | 疑问句降级：只有标题以问号**收尾**才降级（后修正：带答案的设问标题不再降级，否则会误杀处罚报道） |
| 假"多方印证" | 五家媒体转同一篇稿，被当成五条独立证据 | 转载合并 + 同站去重：同立场同标题只留一条 |
| 主体张冠李戴 | 「蛋白质吃多不好」被用来否定「鸡蛋含蛋白质」 | 主体校验：反驳证据标题必须点到断言主体 |
| 数字类误判 | 「高血压诊断标准 140/90」被一篇《别让高血压误区…》判成假 | 数字门：反驳证据标题必须点到断言里的数字 |
| 处罚通报被当噪音 | 郑州「日本引进」案，监管通报在头条/微博转载，按域名只给 2 分权威度 | 官方处罚通报提权：含「市场监管局/行政处罚/处罚决定/违法广告案/查处」→ 权威度补到 4 |
| 广告语判成传言 | 「日本引进」「一盒让三年疼痛消失」走了 3 轮传言检索，判"说不准" | 新增产地/功效广告语词（引进/进口/原装/专利/止痛/疼痛消失）→ 归为宣传宣称，走举证责任倒置 |
| 引号污染关键词 | core 带着「」切词切成"日/本引/进"，跟处罚报道全不匹配 | normalize 剥离「」『』""《》 |

### 2.3 体检入口的两次纠偏（10-23）

| 问题 | 用户原话 | 处理 |
|---|---|---|
| 正常服务文案被判 D | "太严了，用不了" | 拆出四类：服务说明/痛点钩子/经营自述/效果保证。前两类不检索，自述给低风险提示，保证按广告法判中风险（0 检索） |
| 判了假还给 82 分 B | "假的怎么还有 80 多分" | ① 结语区分「与公开来源不符」和「拿不出依据」② 判假每句额外多扣 10 分 ③ 判假句占比 ≥50% → 直接 D（分数封顶 54）④ 修掉 `grade in ("A","B")` 与「B · 小幅修改」字符串不匹配的封顶失效 bug |

### 2.4 受理边界的两处修正（10-23）

| 问题 | 现象 | 修法 |
|---|---|---|
| 医疗词误拦 | 「高血压的诊断标准是 140/90」被判个人隐私拒答 | 医疗/财务类词（诊断/病情/工资/收入）**必须带人物主语**才拦 |
| 时政漏拦 | 「美国下一届总统是谁」被判"真 83" | 补外国政坛词（总统/首相/大选/议会/弹劾/内阁）→ 拒答 0 检索 |

### 2.5 前端与体验（10-23）

| 事项 | 处理 |
|---|---|
| 视觉打磨 | 横幅渐变光晕、卡片渐变、扫光带、按钮呼吸光；≤720px 窄屏光晕缩小减淡 |
| 手机端「上传文本」弹相机 | 系统选择器自带相机入口，网页删不掉 → 手机端改为**不弹选择器**，引导粘贴，按钮文案变「粘贴文本」 |
| 微信内打不开 | 实测微信 UA 访问返回「请在浏览器中打开」（HTTP 403），系统浏览器正常 200 → 所有引导话术改为"复制到浏览器" |
| Word 导航窗格无章节 | docx 由脚本从 md 生成，标题只是直接排版 → 补 `w:outlineLvl`（1/10/7 三级），字体字号不变，PDF 顺带获得书签 |

## 3. 关键设计（为什么这么做）

1. **结论不由模型下**：模型只拆子主张、给单条证据打立场标签；真假由 `judge.py` 按权威层级算。同输入同输出，6 例离线回归每次改代码都跑。
2. **十道闸 + 最后一关三查**：立场标注 / 否定式守卫 / 因果降级 / 转述降级 / 同站矛盾清零 / 同站去重 / 转载合并 / 疑问句降级 / 辟谣标记 / 主体校验，再加企业信用、主体冲突、主题相符 —— 一条证据要过 13 项才进判定。
3. **拒答是架构结果**：个人私事、时政在入口拦下，`searches=0`；证据不足给"说不准"或"没查到"，不给真/假。
4. **两个入口分工**：体检 = 过筛子（每句 3 次，覆盖整段）；核查 = 钻一口井（单句 9 次，挖到能下结论）。
5. **服务类文案不进检索**：能自证的（开了几年、人均多少）给"留存材料"提示；需要外部举证的（除醛率 99%）才查。这是拿真实用户文案调出来的。

## 5. 目录与运行

```
1024侦探/
├─ app.py                  Flask 入口（/、/wall、/stats、/api/verify、/api/checkup、/api/extract）
├─ detective/
│   ├─ claims.py           分类与子主张拆分（含服务类/钩子/自述/资质/保证）
│   ├─ planner.py          三轮检索规划（缺口驱动）
│   ├─ investigator.py     执行检索、组装证据、预算控制
│   ├─ judge.py            十道闸、四套判定口径、五档结论
│   ├─ checkup.py          文案体检链路与打分
│   ├─ lexicon.py          违禁词库 72 条（按法条分类）
│   ├─ rules.py            风险句式、权威度、相关性规则
│   ├─ store.py / cache.py SQLite 存档与 2 小时缓存
│   └─ policy.py           受理边界（个人私事 / 时政）
├─ web/                    首页、查证墙、统计页、卡片页
├─ assets/theme.css        视觉主题
├─ regress/cases.json      6 例离线回归
├─ _test_classify.py       分类器 + 边界单测
├─ _md2docx.py             文档 md→docx 生成（黑体二号/宋体四号/宋体五号）
└─ data/detective.db       记录、证据、统计
```

启动：`.venv/Scripts/python.exe app.py`（默认 5000 端口）
测试：`RUN_MODE=demo python cli.py regress`、`python _test_classify.py`
配置：`.env` 填 `TENCENT_SECRET_ID / TENCENT_SECRET_KEY`；未配置时自动降级为演示数据。

## 6. 已知边界（主动写在作品说明里）

- 不查个人私事、不查时政，入口即拒答（0 检索）
- 不判"推理是否成立"（前提全真、结论也可能推不出来）
- 不判个人资质真假，只提示补证书信息
- 检索本身不确定：同一句隔几分钟再查，证据集可能不同，所以每张卡都标查询时间与检索次数
- 只能引到可访问的来源：高权威站点反爬/付费墙时，宁可"没查到"也不拿营销号凑数
- 微信内置浏览器被托管平台拦截，需用系统浏览器访问

## 7. 用 WorkBuddy 的方式（给评审参考）

全程 Agent 模式对话开发，不是一次性生成：

- **需求靠对话收敛**：从"做个查证工具"到"发布前事实核查"，是在对话里否掉"辟谣助手"定位后定下来的
- **改 bug 靠实测驱动**：每条规则都对应一次线上错误结论，先复现、再定位、再补规则、再回归
- **文档与代码同源**：作品说明由 md 生成 docx（脚本 `_md2docx.py`），数字随线上统计同步更新
- **每次改动都部署并线上复测**：改完必须跑一条受影响的查询，确认结论对得上，才结束
